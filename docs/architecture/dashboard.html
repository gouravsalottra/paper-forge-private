PAPER-FORGE

An auditable autonomous research system for finance / fintech / quant papers: commit hypotheses before consuming results, run bounded simulation research, and retain receipts that let you prove whether the final paper matches the original plan.

control plane data plane serial parallel audit-critical

Moat stack (ordered)

This is the defensibility spine—everything else is implementation detail.

1 — PAP Pre-analysis plan committed and locked before FORGE can start. Prevents “result-driven” refactors.
2 — DataPassport Signed manifest: source, query, rolls, adjustments, lineage—empirical claims become checkable.
3 — CODEC Bidirectional audit: code→spec, then paper→code. Turns consistency into engineering, not vibes.

Why this matters

Finance research fails in predictable ways: silent p-hacking, moving goalposts, irreproducible pulls, code that diverges from prose. This cockpit documents an architecture that makes those failures expensive to commit and cheap to detect.

Why this is defensible

  • SQLite truth for orchestration beats “prompt memory.”
  • Strict lanes prevent cross-contamination of artifacts.
  • Gates encode discipline (PAP → seal → FORGE).
  • Verification stack is a product moat, not a slide.

Architecture summary

One screen: responsibilities, surfaces, and where truth lives.

Layer What it is Source of truth Non‑negotiables
control plane
ARIA		 Parses PAPER.md, builds task graph, routes work, enforces checkpoints. SQLite (state.db): phases, routing, locks, hashes, approvals. Transactional transitions; restart-safe checkpoints; audit trail.
data plane
Agents		 Bounded execution: literature, data, stats, sims, writing, review. Artifact stores (paths) + manifests; referenced from SQLite. Each agent writes only its lane.
verification
PAP + DataPassport + CODEC + HAWK		 Scientific discipline + adversarial pressure. PAP rows + sealed lock; signed DataPassport; CODEC records; HAWK review artifacts. No FORGE before PAP commit + pap_lock seal.
tooling
MCP		 Cross-cutting capabilities (arxiv, data, modal, latex). Not the Day‑1 memory backbone—SQLite remains authoritative. Every tool call should still land as routed steps + hashes where it matters.

Daily mental model

The shortest way to think about the system every morning:

  • Control plane = ARIA + SQLite — phases, locks, checkpoints, routing, hashes.
  • Scientific discipline = PAP + DataPassport + CODEC (+ HAWK as hostile pressure).
  • Heavy work = literature + data + statistics + simulation + paper + review — each isolated by lane.
  • deepagents may arrive later as delegation/runtime — not the Day‑1 memory backbone.

If you cannot point to what changed in state.db and which artifact hash proves it, you are drifting out of the architecture.

System architecture

Control plane vs data plane

control plane owns what is allowed to happen next and proves it in SQLite. data plane owns doing the work and emitting artifacts with stable references.

  • ARIA schedules, routes context, and enforces gates.
  • SQLite stores phases, pap_lock, checkpoints, routing logs, hashes.
  • Filesystem / object paths store bulky artifacts; SQLite stores pointers + content hashes.
  • MCP servers are capability endpoints—not the memory backbone.

Artifact flow (conceptual)

  • SCOUT → literature map
  • MINER → datasets + DataPassport
  • SIGMA → PAP rows → commit + seal in SQLite
  • FORGE → simulation repo + outputs (post‑gate)
  • CODEC → spec + audits
  • QUILL → LaTeX/PDF
  • HAWK → review artifact

Checkpoints are restart-safe savepoints for orchestration state—use them before irreversible transitions.

Surface Used for Why it exists Never do this

MCP servers arxiv, data, modal, latex capabilities Composable tools without making them the brain Don’t duplicate orchestration state outside SQLite

Serial vs parallel

serial Must be serial

  • PAP commitment and ordering of planned analyses.
  • pap_lock seal before FORGE.
  • Phase transitions in state.db (transactional + restart-safe).
  • Final checkpoint approvals (release gates).
  • CODEC mismatch adjudication (decide what truth is before rewriting narrative).

Serialism here is the product: auditability requires a total order on authority.

parallel Can parallelize

  • Literature query branches (bounded).
  • Data retrieval subjobs + validation shards.
  • Multi-seed experiments and hyperparameter sweeps.
  • Independent statistical diagnostics.
  • Review dimension scoring (structured).

Parallelism is for throughput—never for bypassing gates.

GPU + performance engineering

FORGE is the primary GPU consumer. The enemy is fragmentation: tiny jobs, excessive host-device sync, and logging that dominates step time.

Utilization principles

  • Batch rollouts to keep devices fed.
  • Vectorize environments where possible (avoid per-step Python overhead).
  • Stage data to minimize IO stalls before training.
  • Mixed precision where numerically stable (reduce memory + increase throughput).
  • Reduce host-device sync—measure how often you block on tiny tensors.

Reliability + cost

  • Separate training from heavy logging (log less frequently, aggregate metrics).
  • Staged evaluation—don’t run full eval every step.
  • Checkpoint smartly—durable progress without thrashing disks.
  • Profile bottlenecks before scaling out (optimize single-worker first).

Likely bottlenecks: environment stepping, dataloader throughput, checkpoint IO, and accidental per-step Python callbacks.

Failure modes & defenses

What breaks

  • Ghost state: notebooks/MCP become implicit memory.
  • Gate bypass: FORGE starts before seal.
  • Data drift: queries change without DataPassport updates.
  • Code–paper drift: prose outruns implementation.
  • GPU waste: fragmented jobs + sync storms.
  • “Friendly” review: HAWK becomes cheerleading.

How the architecture defends

  • SQLite SoT for orchestration + receipts.
  • PAP + pap_lock hard-stop FORGE.
  • DataPassport binds pulls to claims.
  • CODEC two-pass audit loop + serial adjudication.
  • Lanes prevent cross-write corruption.
  • HAWK structured rubric + required revisions artifact.
